# DNS 日誌分析：找出已淪陷的設備

即使企業已經導入端點管理、弱點修補與資安控管，內部仍然會出現中毒或遭入侵的設備。實務上的重點不是假設事件不會發生，而是能否及早發現並處理。

DNS 日誌是值得優先分析的資料來源之一。
除了單純破壞型攻擊，例如刪除資料、加密檔案或讓系統無法開機，多數入侵行為都需要與外部基礎設施通訊。攻擊者通常需要遠端控制受害設備、下達指令、更新惡意程式，或將資料傳出。
這類通訊常見方式包括：

- 直接連線到 IP 位址
- 透過 DNS 解析 C2 網域後再連線

IP 直連較容易被封鎖，也較難長期維持基礎設施彈性。因此，透過 DNS 解析 C2 網域，是攻擊活動中長期存在的常見模式。

## DNS 日誌能提供什麼線索

DNS 日誌的價值在於，它能記錄每一台內部設備查詢過哪些網域，請務必開啟相關的日誌紀錄。
只要能判斷某些網域具有惡意或可疑特徵，就可以反查是哪一台內部設備曾經查詢過該網域，進一步定位可能已經淪陷的端點。

簡化後的分析目標是：

1. 找出可疑或惡意網域
2. 回查哪些內部設備曾經查詢過
3. 對來源設備進行端點調查

## 基本處理流程

![DNS 日誌分析處理流程圖]({{ '/assets/img/posts/dns-log-analysis-flow.svg' | relative_url }})

實務上可以先採用以下流程：

1. 收集內部 DNS 查詢日誌
2. 依設備、時間、查詢網域整理紀錄
3. 對查詢網域去重
4. 排除高可信度白名單
5. 比對惡意網域或可疑特徵
6. 回推查詢來源設備並進行調查

## 先降低資料量

DNS 查詢量通常不小。單一設備每天可能產生數千到上萬筆查詢，若乘上整個企業的設備數，總量可能達到數百萬、數千萬，甚至更高。

不過，這不代表資料無法處理。透過去重與白名單排除，實際需要分析的網域數量會大幅下降。

白名單可以先從兩類資料建立：

- 公司內部最常被查詢的前 100 到 200 個網域
- 全球常見網站或服務的前 100 到 200 個網域

排名靠前的網域通常代表大量正常使用情境，例如搜尋引擎、雲端服務、作業系統更新、常用 SaaS、CDN 或公司業務相關服務。將這些高可信度網域先排除，可以降低分析噪音。

這個方法不代表排名高的網域一定安全，也不代表排名低的網域一定有問題。重點是，在大量 DNS 紀錄中，必須先降低資料量，才能把分析資源集中在少數異常或未知的查詢上。

## 白名單與黑名單

白名單需要持續擴充，例如：

- 公司上下游廠商與客戶使用的網域
- 內部同仁日常會存取的業務系統
- 合法雲端服務、更新服務與安全產品相關網域
- 經過調查確認為正常的內部常見查詢

黑名單則可以來自威脅情資、公開惡意網域資料、歷史事件累積，以及企業自身調查結果。

重點不是一次建立完整黑名單，而是讓資料持續累積，並定期回饋到分析流程中。

## 結論

DNS 日誌分析的核心順序可以整理為：

1. 先去重
2. 再排除白名單
3. 最後比對黑名單與可疑特徵

只要長期執行這個流程，DNS 日誌就能從大量低價值紀錄，轉變成用來發現內部異常設備的有效線索。
